# 0003: 数值口径(LLM 输出小数比率,前端 ×100 显示 %)

- **Status**: Accepted
- **Date**: 2026-08-11
- **Deciders**: @ronnieliu

## Context

业务里有大量"比率型"指标(增长率、同比、占比、份额、达成率、学术接受度)。表达方式有两种:

| 方式 | 例子 | 适合 |
|---|---|---|
| **小数比率** | `0.1542` | 计算(代码层)/ 排序 / 比较大小 |
| **百分数** | `15.42%` | 展示(用户层)/ 业务报告 |

如果在 LLM 输出层就乘 100,所有后续计算都要除回去,反复出错;如果前端 ×100 显示,展示层和计算层就脱钩了,口径混乱。

## Decision

**全程小数比率,只在最末端 ×100 显示 %**:

1. LLM 输出的 pandas 代码里,所有比率型指标用**小数**(0.99 = 99%)
2. server.py 的 `_build_chart_payload` 与表格渲染**不乘 100**(保留原值)
3. 前端 `formatCell` / 图表标签 / 报告生成:依据 `rules.json` 的 `output_format`(`rate_pct`)决定**是否 ×100 + 加 `%` 后缀**
4. 数值统一保留 **2 位小数**(`decimal_places=2`),对齐 `round(,2)`
5. `format_rules` 里 `multiplier=1` 表示不缩放;如需展示成"万元"才用 `multiplier=10000`

**学术接受度**(医学代表 SFE 场景)就是典型例子:展示为 `0.95`(不带 %),`multiplier=1`,因为这是**得分**不是**百分比**——但易被误读为"95%"。决策是**尊重业务原义**(得分就是 0~1 的小数),展示层不加 %。

## Consequences

**正面:**
- 计算链路全程单位一致,不会有"乘多了 / 除少了"的 bug
- 同一份数据既能画"绝对值"图也能画"占比"图,不用回 LLM 重跑
- 展示口径完全由前端控制,改展示不用动 LLM 代码

**负面/成本:**
- 业务方看 `0.1542` 可能一脸懵,需要 UI 在 rate_pct 列明确显示 `15.42%`(前端 `formatCell` 兜底)
- 学术接受度这种"得分型"指标展示成小数容易引发"是不是忘乘 100"的疑问——需要在 prompt 与文档里明确说明
- 任何新增比率字段必须在 `format_rules` 加条目,否则会用全局默认值(可能不符合预期)
