# 0005: 单 HTML 前端 + 内部分块标记

- **Status**: Accepted
- **Date**: 2026-08-14
- **Deciders**: @ronnieliu

## Context

DataAgent 前端是**单文件 HTML**(`web/static/index.html`),1703 行,包含 HTML 骨架 + CSS + 全部 JS 逻辑。考虑过拆模块:

- ES modules(原生 `<script type="module">`)
- Vite 构建产物
- 多个 HTML 页面

但本项目特性:
- 单页工具型应用,1 用户 / 1 部署 / 单次会话流程
- 没有路由切换 / 视图拆分需求
- FastAPI 直接 `app.mount("/static", StaticFiles(...))` 挂载,无构建步骤
- 引入构建系统会增加"代码改完必须 npm run build 才能用"的摩擦

## Decision

**保持单文件**,但做内部分块标记约束膨胀速度:

1. CSS 按组件分节,每节用 `/* ============ 节名 ============ */` 包裹
2. JS 区域顶部加**模块索引注释块**,列出所有模块与关键函数
3. 每个模块的首函数前插一行 `// ──────────────── 模块名 ────────────────`
4. 文件顶部用 markdown 注释(便于后续工具解析)给出 TOC
5. 不引入构建系统;不拆多文件;不引入框架

**触发重构的阈值**(暂定):
- 文件涨到 ~3500 行
- 出现"找代码费时 / 调试困难 / 想加测试但写不出"
- 单次改动需要修改 3 个以上不相关的 JS 区域

到任一阈值时,**优先抽 `formatCell` / `safeMarkdown` / `escapeHtml` 这类纯函数**到独立 JS 文件 + 加单元测试,不整体重构。

## Consequences

**正面:**
- 部署零摩擦(FastAPI 直接挂,改完浏览器刷新生效)
- 没有构建系统学习成本,新人当天能上手
- 全部代码一处可见,小改动不必跳文件
- 内部分块标记让快速定位仍然可行(已加 TOC + 5 个模块分块标记)

**负面/成本:**
- 1703 行单文件,变量名冲突风险随代码量上升
- 没有构建工具 = 不能用 TS / ESLint / Prettier / Tree-shaking
- 全局作用域,难以单元测试(`formatCell` 等纯函数也跑不出隔离测试)
- 浏览器缓存可能让"改完不刷新生效"——必要时强刷

**关联约束**(前端历史约束,AGENTS.md 第 60 行):
- 改样式可以,**所有 `id`/`class` 钩子/`data-*` 绑定与 JS 逻辑不能动**
- 图表渲染在 Python 端 iframe,前端只承担嵌入入口——这隔离了大部分复杂度
